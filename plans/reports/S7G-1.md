# S7G-1 report

Status: done. Branch wp/S7G (not pushed, not merged).

## Done
1. Gantry lever (`planner/solve_gantry.py`, commit 66a1a3a): searches one E1 for the whole program within
   `gantry.limits_mm`. It tries 250 mm steps first, nearest the current E1 first, then 50 mm steps round the
   best one, and keeps the E1 with the fewest find_issues points. With a collision checker it stays within
   solve_e1.MAX_SHIFT_MM of the checker's E1. It runs before the per-layer `e1` lever. The E1 goes on
   move 0, made a gun-off PTP; a gun-off PTP copy is put in front if move 0 sprays. Per-move E1 values are
   dropped. `SolveReport.suggested["gantry_e1"]` is new. Simulate shows a "Suggested gantry E1 = … mm" row
   (gui/checks.solve_checks) and an "Apply suggested set-up" button, which sets the E1 box, so
   `_work_cell` uses it.
2. Purge lever (`planner/solve_purge.py`, `purge.move_purge`, commit 420e992): only runs when issues are on
   moves tagged `purge`. It tries the 26 offsets {-200, 0, +200} mm in X/Y/Z, smallest first. The purge poses
   are translated in WORLD and keep their orientation, so spray_dir and roll stay the same. The clearance
   vias are redone. It keeps the offset with the fewest issues and stops once no purge move has problems
   left. The new point is in `suggested["purge_point"]` and shows as a row. Apply sets the Position-step
   purge X/Y/Z boxes and cell.purge.point. Note: it does not re-run add_purge. The solver only has the
   already purged and gun-levelled path, and add_purge cannot be undone exactly because the gun_on and PTP
   flags are overwritten. So it moves the existing purge poses instead.
3. Purge vias on every trip (commit eccd194): `_clearance_vias` was replaced by `_vias` and `_add_vias`. Every
   change between a purge move and a part move gets vias over the part box when the straight line crosses
   it. That covers the start, mid-run every-N trips (out and back) and also the end trip.
- Both new levers use the "Solver: trying …" log (LEVER_LABELS). SolveOptions has new `gantry` and `purge`
  flags.

## Not done

- The gantry search re-checks the whole path for each candidate, up to about 23 + 9 find_issues runs. With
  the collision checker on a big part this can be slow.
