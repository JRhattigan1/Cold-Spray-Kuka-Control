# S8G-1: gantry / purge levers speed-up
Status: done (exact speed-up only, results identical); the gain is small on repair_surface.
Bench (tools/bench_solve.py from wp/S8B, --only repair_surface block_layers, PC loaded, so times are noisy):
- before: repair_surface 175.4 s (gantry lever 41.0 s), block_layers 27.4 s (gantry 0.8 s); checker.check 56269
- after:  repair_surface 94.4 s (gantry lever 27.2 s), block_layers 29.5 s (gantry 1.0 s); checker.check 56198
- --compare base/new: both IDENTICAL (fixed, unfixed, suggested, poses at 1e-9). The other levers also got about 2x faster
  between the two runs, so most of the drop is load noise. The real saving is about 70 checks.
Done:
- solve_gantry.count_issues(path, ctx, limit): same as find_issues(...)[2], but it stops collision-checking once the count is
  over `limit` (it then returns limit+1 items). IK runs over the whole path and ctx.last is set as in find_issues, so
  the levers after it are unchanged. It uses S8F's solver._sampled / solver._check when they are there (getattr), so
  it keeps their caches working after the merge.
- gantry: each candidate is counted with limit = best score so far (exact: a pruned candidate is strictly worse).
- purge: each offset is counted with limit = best_n - 1 (exact: the list is complete whenever it beats best_n).
- Earlier: candidate E1 rounded to 1e-6 mm and clamped into limits_mm (S8I crash).
Why it barely helps: profile of the gantry lever on repair_surface (58 s, 17 candidates). Every candidate has 773-782
problem points, and about 75% of the roughly 1057 checked samples per candidate collide, so a worse candidate is only
known to be worse near the end. 40 s of the 58 s is fcl collision (_fcl_collide_callback 23 s, _place 30 s cumulative).
Not done (each changes results or needs code I don't own):
- Sample once and vary only E1: not done. axis_defaults E1 plus angle_step sampling can change the sample count with E1, so it isn't
  safe to be exact, and S8F's per-path cache already covers repeat sampling.
- Purge scored with issues_in on purge moves only: not exact. The IK seeds of later part moves depend on the purge joints,
  and moves after the purge visits change count. Left as full counts with early stop.
- Subsample scoring: all candidates are within 9 points of each other, so a subsample would very likely pick another E1.
  Not done, as asked (prefer identical).
- Real gain needs faster collision checks (sim/collision.py: _place / fcl), or a coarser gantry search with a checker.
