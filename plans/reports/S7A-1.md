Branch `wp/S7A`, merged from `wp/K1` (4599a60) into main (29cefc0).

## Done
- **Merge.** Conflicts were in `post/krl.py` and `toolpath/model.py`. Main's behaviour is kept:
  - `program_joints` PTP joints, the NaN-seed warning, and `KRLOptions`/preflight;
  - K1's `joints=` parameter is dropped, because `program_joints` replaces it.
  - K1's additions are kept: the `KRLError` for a CIRC that changes E1, `move_length` for uncoupled speeds, a CIRC on a turning uncoupled table written as 2 LINs, the `$CIRC_TYPE`/`$ORI_TYPE` header, and C_DIS before a CIRC.
  - `Toolpath._with_poses` (main) now carries `aux`: `transformed` maps it with `t @ aux` and `rolled` with `aux @ r`.
- **Option, off by default.** `ProcessConfig.arcs: bool = False` (advanced). It is also in `config/process.yaml` and shows as a check box in the process form.
  - `pipeline._hold_gun` runs `simplify` only when it is on.
  - With the option off, the default KRL is byte-identical: the 3 hashes in `test_krl_regression` are unchanged.
- **Move walkers with CIRC:**
  - `Toolpath.sample` samples along the arc (from K1). `program_joints`, solver `find_issues`/`issues_in`, collision and the timeline all use `sample`, so they follow the arc.
  - `krl_split` `_MOTION` now matches `CIRC`, so the split never cuts after a blended CIRC.
  - The time estimate (`estimate_time_s`) uses the arc length. `sample_times` sums sample chords, which is within 1% of the arc length (tested).
  - `checks._flips` treats CIRC as non-PTP. That is correct: no joint flips are allowed inside an arc.
  - `solve_angle` tilts `aux` (K1).
  - `solve_route` only touches gun-off, approach, jump and purge moves, so it never touches a CIRC. It lifts an end only when the next move is also free.
  - `solve_e1` writes E1 on gun-off moves only, so a CIRC never carries an E1 change. If one did, `to_krl` raises `KRLError`.
  - `add_purge` and `level_gun` run before `simplify`.
- **Regression with arcs on:** test_block `0ee6266a…`, the same as K1's hash: 24 CIRC, LIN 909 → 595.
  - test_repair and test_tube come out identical with arcs on (no CIRC), so no extra hashes were added for them.
  - Arcs on, `split_krl(…, 500)` keeps all 24 CIRCs.
- **Tests added:**
  - `test_arcs_off_by_default` and `test_krl_output_with_arcs_unchanged` (test_block);
  - `test_krl_split::test_circ_is_a_motion_line`;
  - `test_simplify::test_arc_time_and_transforms`.
