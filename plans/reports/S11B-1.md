# S11B-1: KRL base picker methods

**Status:** done (all requested parts in place; hover tested by calling the handlers, not by a real mouse).

## Done
- `cad/part.py`: `krl_base_from_planes` (origin at the three planes' meeting point, Z = 1st face normal,
  X along the 1st/2nd line, sign: toward the part's vertex centroid, i.e. into the part; ValueError when any
  two are within 10 deg of parallel or the 3rd is near-parallel to the line), `vertex_edges`,
  `krl_base_at_vertex` (X = rim edge closest to the cursor direction), `spin_frame`, `flip_z`; `_face_rim`
  shared with `krl_base_frame`. `Part.without` keeps a base with `krl_base_face` None.
- `sim/part_view.py`: `start_pick(..., hover=)` (MouseMoveEvent, throttled to ~30/s), `hover_triangle`,
  `show_preview` (sphere + 0.4-opacity arrows), purple highlights for `krl*` kinds.
- `gui/steps/part.py`: method combo (Face + edge default; existing output unchanged), 3-plane flow with hints
  and highlights, vertex flow (cKDTree once per pick, snap radius 5 % of the part size, renders only when the
  preview frame changes), spin box (-180..180, wrapping) with -90/+90, Flip Z; label shows how it was made and
  the spin/flip. `job_menu.apply` restores through `_set_krl_base` so spin/flip start from the saved base.
- Job format unchanged (no version bump): `krl_base_face: None` already round-trips; the saved base is the
  final (spun/flipped) one.
- Tests: 4 maths tests in `tests/test_krl_base.py`, `tests/test_krl_base_gui.py` (all three methods,
  spin/flip, panel <= 398 px), a job_io round-trip with no face. README Part step, HAND_CHECK section 6.
