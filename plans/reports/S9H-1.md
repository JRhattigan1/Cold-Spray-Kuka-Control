# S9H-1 report

Status: done (tasks 1-3 + finding 8 check) on wp/S9H. Not pushed. KRL unchanged (regression hashes pass).

## Done
1. **HOME legs in the solver.** `find_issues` now also checks the KRL's HOME -> first point and last point -> HOME (`solver._home_issues`). It reports at most one Issue per leg and kind, at the first or last sample (move 0 / last move). The detail names the leg, e.g. `HOME -> first (LIN): A3/Wall` or `last -> HOME: A3/Wall`. A LIN leg that leaves reach gives an `unreachable` Issue. The legs are skipped when `ctx.seed` is set, because the path does not start from HOME. They are also skipped when `limit` is already exceeded. `issues_in` and the levers' local re-checks do not include the legs, so a leg problem is seen by the after-check and reported, but no lever targets it directly.
2. **HOME -> first as the KRL issues it.** The new `solver.home_first_leg(robot, home, target0, q0, ptp)` returns a PTP joint sweep when move 0 is a PTP. Otherwise it returns a LIN: the TCP goes in a straight line from FK(HOME) to the first target, with orientation slerped, and IK is chained from HOME (NaN = unreachable). `CollisionChecker.check_path(..., first_leg=)` takes these joints, and NaN rows are skipped. Simulate passes them through the new `SimulateStep._home_first_leg`, built from the scene's samples and frames. last -> HOME is always a PTP, as in the KRL.
3. **Drawn path.** In `viewer.Scene._draw_lines` only, line points are now the FK of the simulated joints, put in BASE. They replace the planned point only where the two differ by more than 1e-3 mm, which means PTP samples (kind PTP or an E1 change). LIN and CIRC samples and unreachable samples are drawn as planned. The result is cached per (joints, samples), so a layer-filter redraw does not repeat the FK.
- **Finding 8 (`Toolpath.sample` axis fallback):** covered. Every sampling caller passes `initial=axis_defaults(cell)`: the viewer, solver `_sampled`, solve_arm and post/joints. solve_angle's window samples moves whose axes are already filled from `_full_axes(initial)`. The leftover "last value in the path" fallback only applies to axes the cell does not define, and the KRL never writes those. No change.
