# S5-1: "Solve problems" in Simulate (attempt 2)

**Status:** done.

## Done
- `gui/steps/simulate.py`: "Solve problems" button in the Simulate checks. `_solve` submits
  `planner.solver.solve(path, Context(robot, cell, checker, log=...))` to the collision worker
  `self.pool`; the checker is read on the worker (where it is built). `log` only appends to a list;
  the poll (GUI thread) shows the latest line in the job bar. `_poll_check` now polls both the solve
  and the collision check and keeps the timer alive while either runs.
- Cancel (JobProgress): offered; the log callback raises once Cancel is pressed (stops between
  levers), and a result that arrives after Cancel is dropped, so the old path is kept.
- Stale results (new Generate / set-up bumps `check_id`) are dropped without clobbering a newer job bar.
- On success: `_show_solved` replaces `self.result`'s path and redoes Generate's flow (scene/IK,
  slider, unreachable count, checks, program, invalidate Simulate, collision check or mark done).
- `gui/checks.py`: `solve_checks(report)` rows: one ok row per `report.fixed`, one bad row for
  `report.unfixed` (Go to the first point, list of up to 5). Passed through `simulate_checks` /
  `export_checks` while the report still belongs to the shown path.
- Export: Save KRL disabled while unreachable points or unfixed solver problems remain.
- Button disabled while a check or solve runs.
- `sim/viewer.py` `set_path`: IK seeded with `hint=path.hint_for(s.move_index)`.

## Not done
- `export.py` `_save_krl` open-items prompt does not include solver rows (not an owned file; the button is disabled instead).
- The solver has no cancel hook of its own; Cancel takes effect between levers.
