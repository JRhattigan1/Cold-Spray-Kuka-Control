# S11H-1: HOME editor

Status: done (widget + save_home + tests); not yet wired into the Cell dialog (owner: app.py agent).

Done
- `config_io.save_home(home_deg, path=None)`: rewrites only the `home_deg: [...]` line of cell.yaml
  (trailing comment kept, CRLF kept, appended if missing); everything else byte-identical.
- `gui/home_editor.py` `HomeEditor(win, path=None)`: A1-A6 spin boxes (deg, tooltips show robot.yaml
  limits; out-of-limit values allowed and flagged in the status line) + E1 (gantry, default
  cell.gantry.position_mm, range = limits_mm). Signal `pose_changed(list, float)`.
  While visible, each change does `win.scene.set_placement(robroot, gantry_offset)` + `set_robot_pose(q)`.
  Status line: collisions via `win.checker.check(q, axes)` (table axes from `win._table_axes`, plus E1),
  or "checker not ready (run Simulate once)" when `win.checker` is None.
  "Reset to cell.yaml" -> live cell values; "Save to cell.yaml" -> save_home + `cell.home_deg = q`
  on `win.assets.cell` (the live CellConfig Simulate/KRL read via _work_cell).
- Wire-in: `dlg.add_tab(HomeEditor(win), "HOME")`.

Not done / notes
- The checker in `win.checker` is cropped at the E1 it was built at (`checker_e1`); a different E1
  in the editor is followed by `check(... axes[E1])` (_follow_e1), as Simulate does.
- After leaving the tab the robot stays at the edited pose until the next `_enter_setup`;
  the dialog may want to call `win._enter_setup()` on close.
- Not smoke-tested against a real MainWindow (offscreen assets don't load; ad-hoc script hit a
  scipy DLL load error in Git Bash); tests use a stub win.

Test: `pytest -q tests/test_home_editor.py tests/test_config_io.py` -> 6 passed.
