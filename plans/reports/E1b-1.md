# E1b-1: Toolpath process form hooked into Simple/Advanced mode

**Status:** done (green)
**Branch:** `wp/E1b` (worktree `C:\Users\qrb21117\worktrees\cs-E1b`)

## Done
- `toolpath.py`: new `advanced_row(text, box, default)` puts label + editor + `Chip` in one row widget and registers it with `widgets.advanced(row, changed=box_differs(...), chip=chip)`. Every advanced-level field in the Advanced section goes through it (basic fields unchanged).
- `_process_changed` split: `_sync_advanced()` sets the section's "N changed" chip, calls `widgets.refresh()`, and shows or hides the Advanced Section. `_process_changed` = `_sync_advanced()` + invalidate the toolpath (as before).
- `widgets.on_mode_changed(... _sync_advanced)` registered when the panel is built; `_sync_advanced()` also runs once at build time.
- Test `tests/test_process_form_mode.py`: row hidden in Simple, visible with "changed" chip once edited, chip cleared in Advanced.

## Not done
- [ ] Section is not opened automatically in Simple mode when it holds a changed value (stays collapsed by default; the section chip shows "N changed").
- [ ] Text fields (e.g. `turn_plane`) count toward the section's "changed" total, so the section can show in Simple with no visible row if only that differs. Edge case, left alone.
- [ ] Rows no longer align with the QFormLayout label column (label min width 140 px instead).

## Decisions
- The "Advanced" collapsible Section stays. In Advanced mode it always shows; in Simple mode it shows only when at least one advanced value differs from process.yaml.
- Registered the whole row (not the box) so the label hides with it, and so the registry owns that row's visibility only.
- Mode switches do not invalidate the toolpath (only real edits do), hence the `_sync_advanced` split.
