# S9U-1: Position step undo / redo

**Status:** done.

## Done
- New `gui/undo.py`: snapshot stack (cap 50) of the Position step state. Each snapshot holds the placement, mount, keep on plate, substrate on/size, nozzle, tilt, rotation, E1, roll and the constraint rows (with fix poses).
- Coalescing: edits restart a 400 ms single-shot timer, and the snapshot is committed when it fires. Undo/redo commits any pending edit first. Drags already commit only on release (`_part_dragged` final).
- Restore sets the widgets with their signals blocked, rebuilds the constraint rows and sets the part placement exactly as saved. It then calls `scene.set_part_placement` and `_enter_setup`, so the toolpath is marked out of date and is not regenerated.
- Shortcuts: Ctrl+Z undoes, Ctrl+Shift+Z and Ctrl+Y redo. They work only in the Position step; on any other step the status bar says so. There are small ↶ / ↷ buttons in the step bar next to Job, not in the sidebar, so the sidebar width is unchanged.
- History resets when a new part enters the cell (`_enter_cell`).
- `constraints_panel.py`: `rows_state()` / `set_rows()`. `set_rows` emits no `changed` signal.
- `position.py`: `_undo_touch()` hook in `_set_placement`, `_spacemouse_part`, `_auto_positioned` and `_enter_cell` (reset).
- `app.py`: import plus one `undo.install(self)` line.
- `job_menu.apply` was not reused because it reloads the whole job and part. Row serialisation mirrors `job_menu.collect`.

## Not done
- Purge point edits are not in the undo history.
- Opening a job leaves its constraint and placement edits as undoable steps instead of resetting the history.
- When a spin box has keyboard focus, its own text undo takes Ctrl+Z (Qt shortcut override).
